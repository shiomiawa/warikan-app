# 割り勘アプリ 詳細設計書

全体図は `warikan_design_overview.md` を参照。本書は画面・データ構造・計算フローの詳細を定める。

## 1. 基本方針

- 精算の金額はすべて整数(円)で扱う。小数が出る計算は、最後に整数へ丸める
- 外貨・比率(%)・種類の追加は「9. 追加仕様」を参照(本書の古い記述より優先)
- 画面の文言はすべて日本語
- スマートフォンで使いやすいレイアウトにする(縦1列、タップしやすいボタン)
- 保存先は当面ブラウザのローカルストレージ。共有機能は後日 Supabase で追加する

## 2. 画面と遷移

| # | 画面 | 内容 |
|---|---|---|
| 1 | イベント作成 | イベント名、種類(飲み会/旅行など)、端数処理(1円/10円/100円) |
| 2 | メンバー登録 | ニックネームを追加・削除 |
| 3 | 支払い項目一覧 | 項目の一覧、追加ボタン、ETCの状態表示、「精算する」ボタン |
| 4 | 支払い項目の入力 | 種類を選び、種類ごとの入力欄と負担設定を入力 |
| 5 | 精算結果 | 明細、相殺後の送金一覧、テキストコピー |

遷移: イベント作成 → メンバー登録 → 支払い項目一覧 ⇄ 支払い項目の入力 → 精算結果

## 3. データ構造

```ts
type Event = {
  id: string;
  name: string;
  kind: string;                    // 飲み会・旅行など
  rounding: 1 | 10 | 100;          // 端数処理の単位(円)
  members: Member[];
  items: Item[];
};

type Member = { id: string; nickname: string };

type Item = {
  id: string;
  name: string;
  kind: 'normal' | 'gasoline' | 'etc';
  payerId: string;                 // 立て替え者
  amount: number;                  // 通常項目の金額。gasoline/etc は計算値
  split: Split;
  gasoline?: Gasoline;
  etc?: Etc;
};

type Split =
  | { mode: 'equal' }                                   // 均等割り(全員)
  | { mode: 'ratio'; ratios: Record<string, number> }   // memberId → 比率(0は対象外)
  | { mode: 'amount'; amounts: Record<string, number> };// memberId → 負担額

type Gasoline = {
  inputMode: 'odometer' | 'distance';
  odoStart?: number;               // km
  odoEnd?: number;                 // km
  distanceKm?: number;             // 直接入力時
  fuelEconomy: number;             // km/L
  unitPrice: number;               // 円/L
};

type Etc = {
  entryIc: string;
  exitIc: string;
  passedAt: string;                // 日時(ISO文字列)
  vehicleClass: string;            // 車種区分
  discount: string;                // 深夜・休日など
  estimated?: number;              // 概算額
  confirmed?: number;              // 確定額
  status: 'none' | 'estimated' | 'confirmed'; // 未入力・概算・確定
};
```

- `Etc.status` は金額の入力状況から決める: 確定額あり=確定、概算額のみ=概算、どちらもなし=未入力

## 4. 計算フロー

### 4.1 項目金額の確定

| 種類 | 金額 |
|---|---|
| 通常 | 入力された金額 |
| ガソリン | 距離 ÷ 燃費 × 単価(距離はオドメーター差、または直接入力)。四捨五入して整数にする |
| ETC | 確定額があれば確定額、なければ概算額、どちらもなければ0 |

### 4.2 項目ごとの負担額

- **均等割り**: 全員の比率を1として比率指定と同じ計算を行う
- **比率指定**: 本人の負担額 = 金額 × 本人の比率 ÷ 比率の合計。比率0は対象外(負担0)
- **金額指定**: 入力額をそのまま使う。合計が項目金額と一致しない場合は入力エラーとして知らせる

端数処理:

1. 立て替え者以外の各人の負担額を、端数処理の単位で切り上げる
2. 立て替え者の負担額 = 項目金額 − 他の人の負担額の合計(端数の余りは立て替え者に寄せる)
3. 立て替え者が対象外(比率0)でも、余りは立て替え者が吸収する

### 4.3 各人の収支

収支 = 立て替えた金額の合計 − 負担額の合計

- 正: 受け取る側 / 負: 支払う側
- 全員の収支の合計は必ず0になる

### 4.4 相殺(送金回数の最少化)

1. 収支が0でない人を、受け取る人と払う人に分ける
2. 受け取る人の最大額と、払う人の最大額を組み合わせ、小さいほうの額を送金する
3. 送金した額を両者の収支から引き、0になった人を除く
4. 全員が0になるまで繰り返す

この貪欲法で、送金回数は最大でも「収支が0でない人数 − 1」回に抑えられる。

## 5. 精算結果画面

- **明細**: 項目ごとに、各人の負担額を表で表示
- **相殺後**: 「AさんがBさんに ○○円払う」の形式で一覧表示。送金が不要な場合は「精算は不要です」と表示
- **共有**: 結果をテキストでコピーできる(URL共有は将来対応)

## 6. 保存

- イベント・メンバー・支払い項目を、ローカルストレージにJSONで保存する
- 起動時に読み込み、データが壊れている場合は空の状態で始める

## 7. 実装の順序

1. 基本機能(イベント、メンバー、通常項目、負担設定、端数処理、精算結果)
2. ガソリン代
3. ETC
4. ローカルストレージ保存
5. GitHub Pages で公開

## 9. 追加仕様

### 9.1 種類

- イベントの種類: 旅行・飲み会・食事会・BBQ・キャンプ・ゴルフ・その他(自由入力)
- 支払い項目の種類: 食事・飲み会・宿泊・交通・観光・レジャー・買い物・ガソリン代・ETC・その他(自由入力)
- 通常項目の種類名は `Item.category` に保存する。自由入力が空なら「その他」

### 9.2 外貨(米ドル・韓国ウォン)

- 通常項目ごとに通貨(`Item.currency`: JPY / USD / KRW)を選ぶ。ガソリン・ETCは常に円
- 為替レート(1通貨単位あたりの円)はイベントごとに持つ(`Event.rates`)。初期値は目安で、利用者が直す
- 項目の円換算額 = 四捨五入(金額 × レート)。以降の負担額・相殺はすべて円(整数)で計算する
- 金額指定は項目の通貨で入力し、立て替え者以外の各人の額を円に換算、換算の端数は立て替え者に寄せる
- 米ドルは小数2桁まで入力できる

### 9.3 比率指定(%)

- 比率はパーセント(整数)で入力し、合計が100%でないと保存できない
- 1人の%を上げても合計が100%を超えないよう、上限で止める。ゲージで各人の割合と残りを表示する
- 旧データの比率(例 7:3:0)は、編集画面を開いたときに合計100%のパーセントへ直す

### 9.4 精算結果

- 最上部に「最終的な精算表」(払う人 → 受け取る人・金額)を表で表示する
- 各人の収支表(立て替えた額・負担額・差額)と、項目ごとの明細を続けて表示する
- 外貨を使った場合は換算レートを表示し、コピーするテキストにも含める

### 9.5 日付と並べ替え

- 支払い項目は日付(`Item.date`、YYYY-MM-DD)をカレンダーで入力する。新規は今日が初期値
- 一覧・明細は新しい日付が上、古い項目が下。同じ日は後から追加したものが上、日付なしは一番下
- 一覧は日付ごとに見出しを付けてまとめる

### 9.6 メンバーとアバター

- メンバーは最大10人
- 各メンバーは顔の絵文字と色のアバター(`Member.avatar`: 0〜9)を持ち、他のメンバーと重ならない
- 画面のメンバー名(立て替え者・精算表・明細など)は、アバターと同じ色の文字で表示する

### 9.7 高速代(旧ETC)

- 画面上の名称は「高速代」(データ上の種類は `etc` のまま)。概算額・確定額の2本立ては廃止
- 「手入力」か「自動計算」のどちらかを選ぶ
  - 手入力: 金額をそのまま使う(旧データは確定額、なければ概算額を手入力額として扱う)
  - 自動計算: 入口IC・出口ICから地図で距離を調べ、NEXCO普通区間の料金式で計算した目安を使う
    - (150円 + 24.6円/km × 距離) × 車種比率 × 1.1。100km超〜200kmの部分は25%、200km超の部分は30%引き
    - 車種比率: 軽0.8・普通1.0・中型1.2・大型1.65・特大2.75。休日割引・深夜割引は30%引き
    - 都市高速・大都市近郊区間・特別料金区間は考慮しない(目安である旨を画面に表示)

### 9.8 地図からの距離

- ガソリン代は「地図で距離を調べる」を選べる。出発地・目的地を入れて車のルートの片道距離を取得し、往復なら2倍
- 地名検索は OpenStreetMap の Nominatim、ルートは OSRM 公開サーバー(どちらもAPIキー不要)。出典を画面に表示する
- Nominatim の利用規約(1秒1回まで)を守るため、ボタンを押したときだけ呼び出す
- 確認用に Google マップのルート検索へのリンクを出す

### 9.9 入力まわり

- 金額・距離などの数字は矢印(スピンボタン)なしの入力欄にし、全角で入力しても半角にそろえる。スマホでは数字キーボードを出す
- 通常項目の通貨は円が基本で、金額欄の横の小さなボタン(円・ドル・ウォン)で切り替える
- 項目を保存すると「チャリーン」というレジの音を鳴らす(Web Audio で合成)

### 9.10 設定画面(⚙️)

- イベント画面の右上の ⚙️ から設定を開く。タブは「支払い項目」「精算結果」の2つで、メンバーのタブは廃止
- 設定でできること
  - イベント名・種類・端数処理の変更
  - メンバー: 人数を −/＋ で2〜10人に変更し、名前を変える。立て替え者になっている人は削除できない
  - 通貨: 米ドル・韓国ウォンを使うかどうか(`Event.currencies`)と為替レート。使う通貨だけが金額欄の横の切り替えボタンに出る
- イベント作成時も、人数とメンバー名をその場で決める(初期は2人「メンバー1」「メンバー2」)
- アバターは動物の絵文字に統一し、色は赤系を避けた落ち着いた10色(緑・青・オレンジ・茶・青緑・紺・からし・オリーブ・青灰・紫)。人数を増やすと空いている動物を自動で割り当てる(9.6 のアバター選択は廃止)

### 9.11 手入力を減らす

- 項目名は「詳細(任意)」にし、支払い項目の入力の後ろに置く。空なら種類から表示名を自動で付ける
  - 通常項目: 種類名(宿泊・自由入力の種類名など)
  - ガソリン代: 地図で調べた場合は区間付き(例: ガソリン代（東京駅→箱根湯本駅 往復）)
  - 高速代: 自動計算の場合はIC付き(例: 高速代（東京IC→御殿場IC）)
- 新しい項目は、同じ種類の直近の項目から引き継ぐ: ガソリン代は距離の入れ方・燃費・単価・往復、高速代は手入力/自動計算・車種・割引
- 一度入れた地名・IC・自由入力の種類名を入力候補に出す。出発地と目的地(入口と出口)を入れ替えるボタンで帰り道を簡単に入れられる

# 割り勘アプリ 詳細設計書

全体図は `warikan_design_overview.md` を参照。本書は画面・データ構造・計算フローの詳細を定める。

## 1. 基本方針

- 金額はすべて整数(円)で扱う。小数が出る計算は、最後に整数へ丸める
- 画面の文言はすべて日本語
- スマートフォンで使いやすいレイアウトにする(縦1列、タップしやすいボタン)
- 保存先は当面ブラウザのローカルストレージ。共有機能は後日 Supabase で追加する

## 2. 画面と遷移

| # | 画面 | 内容 |
|---|---|---|
| 1 | イベント作成 | イベント名、種類(飲み会/旅行など)、端数処理(1円/10円/100円) |
| 2 | メンバー登録 | ニックネームを追加・削除 |
| 3 | 支払い項目一覧 | 項目の一覧、追加ボタン、ETCの状態表示、「精算する」ボタン |
| 4 | 支払い項目の入力 | 種類を選び、種類ごとの入力欄と負担設定を入力 |
| 5 | 精算結果 | 明細、相殺後の送金一覧、テキストコピー |

遷移: イベント作成 → メンバー登録 → 支払い項目一覧 ⇄ 支払い項目の入力 → 精算結果

## 3. データ構造

```ts
type Event = {
  id: string;
  name: string;
  kind: string;                    // 飲み会・旅行など
  rounding: 1 | 10 | 100;          // 端数処理の単位(円)
  members: Member[];
  items: Item[];
};

type Member = { id: string; nickname: string };

type Item = {
  id: string;
  name: string;
  kind: 'normal' | 'gasoline' | 'etc';
  payerId: string;                 // 立て替え者
  amount: number;                  // 通常項目の金額。gasoline/etc は計算値
  split: Split;
  gasoline?: Gasoline;
  etc?: Etc;
};

type Split =
  | { mode: 'equal' }                                   // 均等割り(全員)
  | { mode: 'ratio'; ratios: Record<string, number> }   // memberId → 比率(0は対象外)
  | { mode: 'amount'; amounts: Record<string, number> };// memberId → 負担額

type Gasoline = {
  inputMode: 'odometer' | 'distance';
  odoStart?: number;               // km
  odoEnd?: number;                 // km
  distanceKm?: number;             // 直接入力時
  fuelEconomy: number;             // km/L
  unitPrice: number;               // 円/L
};

type Etc = {
  entryIc: string;
  exitIc: string;
  passedAt: string;                // 日時(ISO文字列)
  vehicleClass: string;            // 車種区分
  discount: string;                // 深夜・休日など
  estimated?: number;              // 概算額
  confirmed?: number;              // 確定額
  status: 'none' | 'estimated' | 'confirmed'; // 未入力・概算・確定
};
```

- `Etc.status` は金額の入力状況から決める: 確定額あり=確定、概算額のみ=概算、どちらもなし=未入力

## 4. 計算フロー

### 4.1 項目金額の確定

| 種類 | 金額 |
|---|---|
| 通常 | 入力された金額 |
| ガソリン | 距離 ÷ 燃費 × 単価(距離はオドメーター差、または直接入力)。四捨五入して整数にする |
| ETC | 確定額があれば確定額、なければ概算額、どちらもなければ0 |

### 4.2 項目ごとの負担額

- **均等割り**: 全員の比率を1として比率指定と同じ計算を行う
- **比率指定**: 本人の負担額 = 金額 × 本人の比率 ÷ 比率の合計。比率0は対象外(負担0)
- **金額指定**: 入力額をそのまま使う。合計が項目金額と一致しない場合は入力エラーとして知らせる

端数処理:

1. 立て替え者以外の各人の負担額を、端数処理の単位で切り上げる
2. 立て替え者の負担額 = 項目金額 − 他の人の負担額の合計(端数の余りは立て替え者に寄せる)
3. 立て替え者が対象外(比率0)でも、余りは立て替え者が吸収する

### 4.3 各人の収支

収支 = 立て替えた金額の合計 − 負担額の合計

- 正: 受け取る側 / 負: 支払う側
- 全員の収支の合計は必ず0になる

### 4.4 相殺(送金回数の最少化)

1. 収支が0でない人を、受け取る人と払う人に分ける
2. 受け取る人の最大額と、払う人の最大額を組み合わせ、小さいほうの額を送金する
3. 送金した額を両者の収支から引き、0になった人を除く
4. 全員が0になるまで繰り返す

この貪欲法で、送金回数は最大でも「収支が0でない人数 − 1」回に抑えられる。

## 5. 精算結果画面

- **明細**: 項目ごとに、各人の負担額を表で表示
- **相殺後**: 「AさんがBさんに ○○円払う」の形式で一覧表示。送金が不要な場合は「精算は不要です」と表示
- **共有**: 結果をテキストでコピーできる(URL共有は将来対応)

## 6. 保存

- イベント・メンバー・支払い項目を、ローカルストレージにJSONで保存する
- 起動時に読み込み、データが壊れている場合は空の状態で始める

## 7. 実装の順序

1. 基本機能(イベント、メンバー、通常項目、負担設定、端数処理、精算結果)
2. ガソリン代
3. ETC
4. ローカルストレージ保存
5. GitHub Pages で公開

# 割り勘アプリ 詳細設計書

全体図は `warikan_design_overview.md` を参照。本書は画面・データ構造・計算フローの詳細を定める。

## 1. 基本方針

- 精算の金額はすべて整数(円)で扱う。小数が出る計算は、最後に整数へ丸める
- 外貨・比率(%)・種類の追加は「9. 追加仕様」を参照(本書の古い記述より優先)
- 画面の文言はすべて日本語
- スマートフォンで使いやすいレイアウトにする(縦1列、タップしやすいボタン)
- 保存先は当面ブラウザのローカルストレージ。共有機能は後日 Supabase で追加する

## 2. 画面と遷移

| # | 画面 | 内容 |
|---|---|---|
| 1 | イベント作成 | イベント名、種類(飲み会/旅行など)、端数処理(1円/10円/100円) |
| 2 | メンバー登録 | ニックネームを追加・削除 |
| 3 | 支払い項目一覧 | 項目の一覧、追加ボタン、ETCの状態表示、「精算する」ボタン |
| 4 | 支払い項目の入力 | 種類を選び、種類ごとの入力欄と負担設定を入力 |
| 5 | 精算結果 | 明細、相殺後の送金一覧、テキストコピー |

遷移: イベント作成 → メンバー登録 → 支払い項目一覧 ⇄ 支払い項目の入力 → 精算結果

## 3. データ構造

```ts
type Event = {
  id: string;
  name: string;
  kind: string;                    // 飲み会・旅行など
  rounding: 1 | 10 | 100;          // 端数処理の単位(円)
  members: Member[];
  items: Item[];
};

type Member = { id: string; nickname: string };

type Item = {
  id: string;
  name: string;
  kind: 'normal' | 'gasoline' | 'etc';
  payerId: string;                 // 立て替え者
  amount: number;                  // 通常項目の金額。gasoline/etc は計算値
  split: Split;
  gasoline?: Gasoline;
  etc?: Etc;
};

type Split =
  | { mode: 'equal' }                                   // 均等割り(全員)
  | { mode: 'ratio'; ratios: Record<string, number> }   // memberId → 比率(0は対象外)
  | { mode: 'amount'; amounts: Record<string, number> };// memberId → 負担額

type Gasoline = {
  inputMode: 'odometer' | 'distance';
  odoStart?: number;               // km
  odoEnd?: number;                 // km
  distanceKm?: number;             // 直接入力時
  fuelEconomy: number;             // km/L
  unitPrice: number;               // 円/L
};

type Etc = {
  entryIc: string;
  exitIc: string;
  passedAt: string;                // 日時(ISO文字列)
  vehicleClass: string;            // 車種区分
  discount: string;                // 深夜・休日など
  estimated?: number;              // 概算額
  confirmed?: number;              // 確定額
  status: 'none' | 'estimated' | 'confirmed'; // 未入力・概算・確定
};
```

- `Etc.status` は金額の入力状況から決める: 確定額あり=確定、概算額のみ=概算、どちらもなし=未入力

## 4. 計算フロー

### 4.1 項目金額の確定

| 種類 | 金額 |
|---|---|
| 通常 | 入力された金額 |
| ガソリン | 距離 ÷ 燃費 × 単価(距離はオドメーター差、または直接入力)。四捨五入して整数にする |
| ETC | 確定額があれば確定額、なければ概算額、どちらもなければ0 |

### 4.2 項目ごとの負担額

- **均等割り**: 全員の比率を1として比率指定と同じ計算を行う
- **比率指定**: 本人の負担額 = 金額 × 本人の比率 ÷ 比率の合計。比率0は対象外(負担0)
- **金額指定**: 入力額をそのまま使う。合計が項目金額と一致しない場合は入力エラーとして知らせる

端数処理:

1. 立て替え者以外の各人の負担額を、端数処理の単位で切り上げる
2. 立て替え者の負担額 = 項目金額 − 他の人の負担額の合計(端数の余りは立て替え者に寄せる)
3. 立て替え者が対象外(比率0)でも、余りは立て替え者が吸収する

### 4.3 各人の収支

収支 = 立て替えた金額の合計 − 負担額の合計

- 正: 受け取る側 / 負: 支払う側
- 全員の収支の合計は必ず0になる

### 4.4 相殺(送金回数の最少化)

1. 収支が0でない人を、受け取る人と払う人に分ける
2. 受け取る人の最大額と、払う人の最大額を組み合わせ、小さいほうの額を送金する
3. 送金した額を両者の収支から引き、0になった人を除く
4. 全員が0になるまで繰り返す

この貪欲法で、送金回数は最大でも「収支が0でない人数 − 1」回に抑えられる。

## 5. 精算結果画面

- **明細**: 項目ごとに、各人の負担額を表で表示
- **相殺後**: 「AさんがBさんに ○○円払う」の形式で一覧表示。送金が不要な場合は「精算は不要です」と表示
- **共有**: 結果をテキストでコピーできる(URL共有は将来対応)

## 6. 保存

- イベント・メンバー・支払い項目を、ローカルストレージにJSONで保存する
- 起動時に読み込み、データが壊れている場合は空の状態で始める

## 7. 実装の順序

1. 基本機能(イベント、メンバー、通常項目、負担設定、端数処理、精算結果)
2. ガソリン代
3. ETC
4. ローカルストレージ保存
5. GitHub Pages で公開

## 9. 追加仕様

### 9.1 種類

- イベントの種類: 旅行・飲み会・食事会・ショッピング・ドライブ・その他(自由入力)(9.18 で BBQ・キャンプ・ゴルフをはずした)
- 支払い項目の種類: 食事・飲み会・宿泊・交通・観光・レジャー・買い物・ガソリン代・ETC・その他(自由入力)
- 通常項目の種類名は `Item.category` に保存する。自由入力が空なら「その他」

### 9.2 外貨(米ドル・韓国ウォン)

- 通常項目ごとに通貨(`Item.currency`: JPY / USD / KRW)を選ぶ。ガソリン・ETCは常に円
- 為替レート(1通貨単位あたりの円)はイベントごとに持つ(`Event.rates`)。初期値は目安で、利用者が直す
- 項目の円換算額 = 四捨五入(金額 × レート)。以降の負担額・相殺はすべて円(整数)で計算する
- 金額指定は項目の通貨で入力し、立て替え者以外の各人の額を円に換算、換算の端数は立て替え者に寄せる
- 米ドルは小数2桁まで入力できる

### 9.3 比率指定(%)

- 比率はパーセント(整数)で入力し、合計が100%でないと保存できない
- 1人の%を上げても合計が100%を超えないよう、上限で止める。ゲージで各人の割合と残りを表示する
- 旧データの比率(例 7:3:0)は、編集画面を開いたときに合計100%のパーセントへ直す

### 9.4 精算結果

- 最上部に「最終的な精算表」(払う人 → 受け取る人・金額)を表で表示する
- 各人の収支表(立て替えた額・負担額・差額)と、項目ごとの明細を続けて表示する
- 外貨を使った場合は換算レートを表示し、コピーするテキストにも含める

### 9.5 日付と並べ替え

- 支払い項目は日付(`Item.date`、YYYY-MM-DD)をカレンダーで入力する。新規は今日が初期値
- 一覧・明細は新しい日付が上、古い項目が下。同じ日は後から追加したものが上、日付なしは一番下
- 一覧は日付ごとに見出しを付けてまとめる

### 9.6 メンバーとアバター

- メンバーは最大30人(9.18 で10人から変更)
- 各メンバーは色の番号(`Member.avatar`: 0〜9)を持つ。10人を超えたら、いちばん使われていない色をもう一度使う
- 画面のメンバー名(立て替え者・精算表・明細など)は、その色の文字で表示し、前に頭文字のバッジを付ける(9.18)

### 9.7 高速代(旧ETC)

- 画面上の名称は「高速代」(データ上の種類は `etc` のまま)。概算額・確定額の2本立ては廃止
- 「手入力」か「自動計算」のどちらかを選ぶ
  - 手入力: 金額をそのまま使う(旧データは確定額、なければ概算額を手入力額として扱う)
  - 自動計算: 入口IC・出口ICから地図で距離を調べ、NEXCO普通区間の料金式で計算した目安を使う
    - (150円 + 24.6円/km × 距離) × 車種比率 × 1.1。100km超〜200kmの部分は25%、200km超の部分は30%引き
    - 車種比率: 軽0.8・普通1.0・中型1.2・大型1.65・特大2.75。休日割引・深夜割引は30%引き
    - 都市高速・大都市近郊区間・特別料金区間は考慮しない(目安である旨を画面に表示)

### 9.8 地図からの距離

- ガソリン代は「地図で距離を調べる」を選べる。出発地・目的地を入れて車のルートの片道距離を取得し、往復なら2倍
- 地名検索は OpenStreetMap の Nominatim、ルートは OSRM 公開サーバー(どちらもAPIキー不要)。出典を画面に表示する
- Nominatim の利用規約(1秒1回まで)を守るため、ボタンを押したときだけ呼び出す
- 確認用に Google マップのルート検索へのリンクを出す

### 9.9 入力まわり

- 金額・距離などの数字は矢印(スピンボタン)なしの入力欄にし、全角で入力しても半角にそろえる。スマホでは数字キーボードを出す
- 通常項目の通貨は円が基本で、金額欄の横の小さなボタン(円・ドル・ウォン)で切り替える
- 項目を保存すると「チャリーン」というレジの音を鳴らす(Web Audio で合成)

### 9.10 設定画面(⚙️)

- イベント画面の右上の ⚙️ から設定を開く。タブは「支払い項目」「精算結果」の2つで、メンバーのタブは廃止
- 設定でできること
  - イベント名・種類・端数処理の変更
  - メンバー: 人数を −/＋ で2〜30人に変更し、名前を変える。立て替え者になっている人は削除できない
  - 通貨: 米ドル・韓国ウォンを使うかどうか(`Event.currencies`)と為替レート。使う通貨だけが金額欄の横の切り替えボタンに出る
- イベント作成時も、人数とメンバー名をその場で決める(初期は2人「メンバー1」「メンバー2」)
- アバターは動物の絵文字に統一し、色は赤系を避けた落ち着いた10色(緑・青・オレンジ・茶・青緑・紺・からし・オリーブ・青灰・紫)。人数を増やすと空いている動物を自動で割り当てる(9.6 のアバター選択は廃止)

### 9.11 手入力を減らす

- 項目名は「詳細(任意)」にし、支払い項目の入力の後ろに置く。空なら種類から表示名を自動で付ける
  - 通常項目: 種類名(宿泊・自由入力の種類名など)
  - ガソリン代: 地図で調べた場合は区間付き(例: ガソリン代（東京駅→箱根湯本駅 往復）)
  - 高速代: 自動計算の場合はIC付き(例: 高速代（東京IC→御殿場IC）)
- 新しい項目は、同じ種類の直近の項目から引き継ぐ: ガソリン代は距離の入れ方・燃費・単価・往復、高速代は手入力/自動計算・車種・割引
- 一度入れた地名・IC・自由入力の種類名を入力候補に出す。出発地と目的地(入口と出口)を入れ替えるボタンで帰り道を簡単に入れられる

### 9.12 設定の見直し(9.10 を置き換え)

- トップページ右上の「⚙️ 設定」は、アプリ全体の設定(`AppData.settings`、すべてのイベント共通)
  - 通貨と為替レート: 米ドル・韓国ウォンを使うか、レート。旧データはイベントに持っていた値を引き継ぐ
  - ガソリン代の距離の入れ方: 「地図で距離を調べる」が標準で常に使える。「距離を直接入力」「メーターから計算」はチェックしたときだけ選べる
- イベント画面の右上は「✏️ 編集」(イベント名・種類・端数処理・メンバー)。メンバーは設定には置かない
- 高速代の自動計算は「自動で計算する」ボタンで、入口IC・出口ICの距離を調べて料金式で計算し、結果を高速代の金額欄にそのまま入れる
  - 車種・割引を変えると、調べた距離から計算し直す。金額欄は手で直せる(直した額を使う)
  - 精算は常に金額欄の値を使う(`Etc.amount`)

### 9.13 クイック割り勘

- トップページの「⚡ クイック割り勘」から開く、イベントを作らない1回だけの割り勘画面。保存はしない
- 入力: 合計人数(2〜50人)、合計金額、端数処理(1円・10円・100円)
- 結果: 1人あたりの金額。幹事以外は端数処理の単位で切り上げ、余りは幹事が負担する(`quickSplit`)
  - 少額で幹事の負担がマイナスになるときは切り捨てにする
- 結果はテキストでコピーできる

### 9.14 一覧・共有・PayPay

- イベント一覧はタイトルの横に、支払い項目の中で一番古い日付を表示する(今年なら年を省く)
- 一覧は新しい順(項目のないイベントが上、ほかは一番古い日付の新しい順)に最大5件。「すべて表示」で残りも出す
- メンバーの仮の名前(メンバー1 など)は薄い色で表示し、タップすると全選択されてすぐ上書きできる
- 精算結果・クイック割り勘の結果は、LINE・SMS・ほかのアプリ(スマホの共有機能)・コピーで共有できる
  - LINE: `https://line.me/R/share?text=…`、SMS: `sms:?&body=…`
- PayPay: 幹事がPayPayアプリで作った受け取り用リンクを貼ると、QRコードにして表示する(qrcode ライブラリ)
  - 個人がアプリの外から金額入りのPayPay決済QRを作る手段はないため、リンクを貼る方式にしている
  - リンクは設定(`AppSettings.paypayLink`)に保存し、次回から自動で入る。共有する文にも添える
  - https のリンクだけQRにする。PayPay(paypay.ne.jp)以外のリンクには注意を出す

### 9.15 入力の注意とエラー音・負担の割り方の折りたたみ

- 数字を入れ終わったとき(入力欄から離れたとき)、ふつうの範囲から大きく外れていれば「ぶっぶー」とブザー音を鳴らし、欄の下に注意を出す(`src/checks.ts`)。保存は止めない
  - 燃費 3〜40km/L、ガソリン単価 100〜300円/L、距離 3,000kmまで、高速代 50〜50,000円
  - 金額 100万円・1万ドル・1,000万ウォンまで、クイック割り勘の合計 1,000万円まで
  - レート 1ドル 50〜500円、1ウォン 0.01〜1円。メーターは到着時が出発時以下なら注意
- 地名・ICが見つからないとき、自動計算の高速代が範囲外のときもブザーを鳴らす
- 負担の割り方は折りたたみ、見出しに今の割り方(普段は均等割り)を表示する。タップで開いて変更する

### 9.16 クイック割り勘の負担の割り方

- クイック割り勘でも、支払い項目と同じ「負担の割り方」(均等割り・比率指定（%）・金額指定)を選べる。部品は `SplitEditor` を共通で使う
- 名前は入れなくてよいように、1人目を「幹事」(立て替えた人)、ほかを「2人目」「3人目」…とし、頭文字のバッジ(番号)で見分ける
- 比率指定・金額指定の計算は支払い項目と同じ(`itemShares`、端数は幹事に寄せる)。結果は「それぞれの負担額」として一覧で出し、共有文にも全員分を入れる
- 人数を変えたら比率は均等からやり直す

### 9.17 集金チェックとワンタップ傾斜

- クイック割り勘の結果に「集金チェック」を出す。幹事以外で払う額がある人を金額付きで並べ、受け取ったらチェック(チャリーン音)。「◯/◯人済み・残り◯円」を表示し、全員済んだら知らせる。保存はしない
- 比率指定(%)では、人ごとに「多め・ふつう・少なめ・なし」をタップすると%が自動で決まる(重み 1.5・1・0.5・0、`tierPercents`)。スライダーで手直しすると選択は外れる。支払い項目とクイック割り勘の両方で使える
- 全体設計図(`warikan_design_overview.md`)を現在の画面構成に合わせて書き直した

### 9.18 種類の見直し・メンバー30人・頭文字バッジ・PayPayのスクショ

- イベントの種類から BBQ・キャンプ・ゴルフをはずし、ショッピング(🛍️)・ドライブ(🚗)を足した。以前のイベントの種類名とアイコンはそのまま表示する
- メンバーを最大30人にした(クイック割り勘は従来どおり50人まで)
- 動物のアバターはやめ、メンバーの色の丸に白い頭文字を入れたバッジにした(`memberInitial`)。英字は大文字。仮の名前(メンバー12)と「◯人目」は番号を出す。2桁は小さめの数字にする
- PayPay: 受け取りリンクのほかに、受け取りQRコードのスクショを貼れる
  - 画像を選ぶか、パソコンではコピーした画像を貼り付け(Ctrl+V)。長い辺1200pxまでに縮めて WebP(できなければ JPEG)にする(`src/image.ts`)
  - 設定(`AppSettings.paypayQrImage`)に保存し、次回から自動で出る。精算結果とクイック割り勘の結果に、そのまま表示する。共有する文には入れない

### 9.19 1人ずつ送る・受け取る人ごとのPayPayリンク・精算済

- 精算結果の精算表の下に「1人ずつ送る」を置く(`SendList`)。送金ごとに「LINEで送る」「SMSで送る」「精算済にする」を出す
  - 送る文は払う人1人分だけ(`transferText`):「【イベント名】精算のお願い」「◯さん → ◯さん:金額」と、受け取る人のPayPayリンク
  - LINE・SMS の送り先は、開いたアプリで選ぶ(アプリからは相手を指定できない)
- 受け取る人ごとに、PayPay受け取りリンク(任意)を入れられる。イベントのメンバー(`Member.paypayLink`)に保存し、名前でも覚えて(`AppSettings.paypayLinks`)、次のイベントで同じ名前の人に自動で入れる(`memberPaypayLink`)
- 全員に送る共有文では、受け取る人のリンクを各行に添える。誰のリンクもなければ、従来どおり幹事のリンクを最後に添える
- 送金が済んだら「精算済にする」(チャリーン音)。精算表と「1人ずつ送る」の両方で、名前と金額を薄くして取り消し線を引き、「精算済」と表示する。共有文にも「(精算済)」を付ける。全部済んだら知らせる
  - 精算済は `WarikanEvent.paidTransfers` に送金のキー(払う人・受け取る人・金額、`transferKey`)で保存する。項目を変えて金額が変わった送金は、精算済が外れる

### 9.20 幹事が受け取りリンクを集める

- 9.19 の「1人ずつ送る」を「解散後の精算の連絡」にし、幹事が受け取る人のPayPay受け取りリンクを先に集める流れにした(参加者どうしで交流がなくても精算できるように)
- イベントごとに幹事を選ぶ(`WarikanEvent.organizerId`、未設定なら1人目、`organizerIdOf`)。幹事のリンクは設定に登録したもの(`AppSettings.paypayLink`)を使う
- ① 受け取る人のリンクを集める
  - リンクがまだない受け取る人(幹事以外)に、まとめて頼む文(`collectLinksText`、グループのLINE向け)と、1人ずつ頼む文(`receiverText`:誰からいくら受け取るかと、「受け取りリンクを作って、幹事の◯さんに送ってください」)を送れる
  - 届いたリンクを受け取る人ごとの欄に貼る(9.19 と同じく名前で覚えて次のイベントに引き継ぐ)
- ② 払う人に送る(`transferText`):受け取る人のリンクを添える。なければ「PayPayの送り先がわからない場合は、幹事の◯さんに連絡してください」と添える。幹事が払う人の送金には送るボタンを出さない

### 9.21 全体の共有文に明細を入れる

- 幹事だけが中身を知っている状態にならないよう、全員に送る精算結果の文に「■ 明細」(項目ごとの日付・名前・金額・立て替えた人。外貨は「$20.00＝3,000円」)と「■ 各人の収支」(立て替え・負担・受け取る/払う)を入れられる(`detailLines`)
- 共有ボタンの上の「明細と各人の収支も入れて送る」で切り替える。初めはオン
- 長くて LINE の「送る」画面で途中までしか入らないときは、「コピー」して LINE に貼り付けるよう案内する
